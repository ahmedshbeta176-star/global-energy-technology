# مخزون الأكواد الرقمي — حالة الأمان

## ما تم إنجازه
- جدول `digital_vendor_encrypted_codes` محمي دون أي صلاحيات وصول مباشرة لـ `anon` أو `authenticated`.
- خدمة Supabase Edge Function: `digital-code-secure-intake`، تتطلب JWT صالحاً وتتحقق من ملكية الدفعة وموافقة البائع والمنتج والعقد النشط.
- تشفير AES-256-GCM على الخادم مع nonce عشوائي لكل كود، وبصمة HMAC-SHA256 لمنع التكرار.
- تخزين الأكواد في حالة `quarantined` فقط؛ لا يُتاح البيع أو التسليم التلقائي.
- الخدمة ترفض العمل (503) إذا لم يتوفر متغير البيئة `CODE_ENCRYPTION_KEY_BASE64`.

## قبل الاستخدام الحقيقي
1. إنشاء مفتاح عشوائي سري بطول 32 بايت، وتمثيله Base64، وضبطه في أسرار Supabase Edge Functions باسم `CODE_ENCRYPTION_KEY_BASE64`. **لا تضعه في GitHub أو صفحات HTML أو المحادثات.** احتفظ بنسخة آمنة لأن فقدانه يجعل الأكواد غير قابلة لفك التشفير.
2. اختبار الأذونات والمخزون والتكرار وحالات فشل الطلبات بالتوازي. لا يُسمح حالياً باستخدام أكواد حقيقية قبل إتمام هذه الاختبارات.
3. تعزيز إدخال الدفعات المتزامنة بمعاملة/قفل قاعدة بيانات، وإضافة سجل تدقيق وتدوير مفاتيح وتحديد معدلات الطلب.
4. تطوير خدمة تسليم منفصلة لا تُخرج الكود إلا بعد تحقق موثوق من الدفع والترخيص، مع ضمان تسليم كل كود مرة واحدة.
5. التحقق من حقوق بيع وتوزيع التطبيقات والمحتوى قبل تفعيل المنتجات.

## ملاحظة
صفحة لوحة البائع الحالية تعرض خطط المخزون وطلبات التجهيز، ولا تعرض الأكواد نفسها. لا تُدخل أكواداً حقيقية في حقول اسم الدفعة أو الملاحظات.
